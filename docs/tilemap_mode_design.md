## 1. 模式总览

1. **文生瓦片集**：文本描述纹理/风格 → 内置严格 3×3 九宫格提示词（中心=无缝
   纹理、四边=单侧直线边界的墙面瓦片、四角=圆角切角瓦片、纯白背景、统一
   调色板）→ 生图 API。
2. **自适应裁切**：`crop_base_3x3`——单格尺寸 = floor(min(w,h)/3) 取偶，
   整图居中取 3×cell 区域等分裁 9 张；`normalize_tileset` 归一化到目标规格
   （最近邻保持像素硬边）。
3. **逐瓦片重绘**（UI 待做）：复用 `core/editing/canvas.PixelCanvas`。
4. **无缝化算法**（`seamless.py`，确定性、无 AI）：
   - 纹理：顺序镜像平均（先水平后垂直，数学上保证 left==right 且
     top==bottom 逐像素相等），再重量化回原调色板；
   - 墙面：旋转到「边界朝上」，沿边界轴镜像平均（线带不动），四边线带
     统一为同一线色 → 长墙无限重复、四朝向风格一致；
   - 转角：由无缝中心纹理 + 统一线色按位掩码构图推导（构造性零接缝），
     AI 角瓦片仅可选低权重混合内部细节。
5. **47-tile / 双网格**（`autotile.py`，用户可选）：
   - 47 集：8 邻域位掩码（TL=1,T=2,TR=4,L=8,R=16,BL=32,B=64,BR=128）→
     几何构图：空侧画边界线；四角「两侧同空（外角）或两侧同满且对角空
     （内角）」时切半径 s/2 四分之一圆盘（弧线过边中点），弧线描边、弦
     不描边；地形一律取中心纹理。
   - 双网格：同一构图规则在 2 倍分辨率下以 4 类四分之一块（填充/上直切/
     左直切/转角盘）铺出，导出 2× 索引图。
6. **大网格预览**（UI 待做）：`TileMapModel` 铺设/擦除/矩形填充，按邻域
   位掩码自动衔接，`render()` 输出整图（47 或 dual 模式）。

## 2. 47-tile 数学依据

- 全 256 种掩码按视觉等价归并：k=4 全边满 16 种（四内角各由对角位决定）、
  k=3 缺一边 16、k=2 相邻 8、k=2 相对 2、k=1 仅一边 4、k=0 孤立 1，
  **总计 47**。实现为按组枚举 + 图像去重（`_group_masks`）。
- 孤立足（mask=0）与「四内角」（四边满、对角全空）图形重合（同为四角
  圆盘切），经典模板惯例保留两个槽位：实现输出 47 槽、46 张独立图像，
  `meta.mask_to_index` 覆盖全部 256 掩码。
- 无缝性不变量（有测试证明）：随机地图中任意相邻两格共享边上的不透明
  像素**逐像素一致**，唯一允许的差异位于共享边两端 r+2 像素内的转角区
  （内角缺口之「弦」落在相邻瓦片一侧，为 Godot 同款预期外观）。

## 5. 第二轮重构（按用户反馈）

1. **分类生成**：瓦片按功能分为两类：
   - 地块类 = 2×2 生态图（每块 3×3）：左上=纯基础地形（中心无缝纹理 +
     与空白的自然边界）；右上/左下/右下=同一生态下的特征地块（水塘/
     稀疏草地/岩石），特征块中心=特征纯纹理、周边 8 格=特征↔基础的
     直线/圆角过渡 → 同一生态内不同元素无缝融合；
   - 建筑类 = 2×2 建筑图：墙体组（中心=可重复墙面纹理 + 端头/转角）、
     顶面组、开口组（门/窗）、立柱组；建筑外纯白 → 抠除后透明，
     可像图层一样叠放在地块上。
2. **纹理退化修复**：无缝化从全图镜像平均改为**偏移错位缝合**（平移半格、
   仅中央十字缝窄带交叉淡化、平移回来）——接缝窄带外的像素原样保留，
   不再出现「渐变+色块」；单轴版 `make_axis_seamless` 用于边瓦片。
3. **47-tile 构图改用真实艺术片**：`compose_art_tile` 把每张瓦片的 4 个
   四分之一块直接取自九宫格的对应艺术片（中心=填充、边=直线过渡、
   角=圆角过渡，内角=角艺术），块接触带 1px 交叉淡化掩盖 AI 不一致；
   不再程序化描边。`build_47_sheet_art` / `build_dual_pieces_sheet_art`。
4. **多地形 + overlay 地图模型**：`TileMapModel` 支持 terrain id 网格 +
   `terrain_sets`（每地形一套九宫格）；`mask_for_terrain`：基础地形把
   任何非空地形视为满（内部过渡显示填充），特征地形仅统计同地形邻居
   （过渡艺术由特征一侧提供）；`overlay` 层放建筑拼件（直段/端头/转角/
   立柱，带旋转），`process_building_sheet` 抠白底 + 派生拼件。
5. 测试：`tests/test_tilemap_eco.py`（缝合保纹理/生态裁切/艺术构图映射/
   47 计数/多地形掩码/overlay）。
6. UI 与工作流已接入：`tilemap_workflow.py` 按 category 分支（ground=生态
   多地形 47 艺术集导出；building=拼件导出 + 摆样预览；classic=旧链路）；
   `tilemap_page.py` 类别选择 + 特征槽 + 按瓦片组编辑 + 多地形画笔；
   `tilemap_view.py` 地形画笔切换与建筑拼件放置（选择 + 旋转 + 图层）。
   待办：实机验收（真实生图服务商 2×2 生态图/建筑图的裁切对齐与融合效果）。

## 8. 第四轮：参照 FrameRonin 修正（关键 bug）

参考对象：`frameronin.com` 为 SPA（无源码可爬），改用其开源仓库
`systemchester/FrameRonin` 的实现（本地 `.tmp/refs/FrameRonin`），
核心参考 `frontend/src/components/infiniteMap/blobTerrain.ts`：
`computeBlobMask`（掩码约定）、`MASK_TO_INDEX`（47 槽索引表）、
`nearestBlobTileIndex`（汉明距离回退）。

学到的两条关键规则（此前实现缺失，正是「拼接很烂」的根因）：
1. **对角位必须依赖正交位**：`n && w && has(-1,-1)` 才计入 TL 位（TR/BL/BR 同理）。
   此前我们无条件计入对角位 → 产生大量非经典邻域（如「只有对角邻居」），
   派生出错误瓦片；改为 `canonical_mask()` 规范化后，**可达掩码恰好 47 个**，
   与 47 槽一一对应。
2. **任意掩码用汉明距离回退到最近合法掩码**（`nearest_mask`），导出的
   `mask_to_index` 因此对全部 256 种邻域都有确定答案。

本轮修复的 bug：
- `mask_from_neighbors` / `mask_for_terrain` 未规范化对角位（见上，核心 bug）；
- `build_47_sheet_art` 改为枚举 47 个可达掩码 + 全 256 映射 + `reachable_masks`
  元数据（槽位稳定，不再依赖去重顺序）；
- `compose_art_tile` 接触带融合**写回顺序 bug**：第二次写回读了已被改写的
  邻居列/行，导致中线左右不对称的脏边（已用副本修复，并有对称性测试）；
- `TileMapModel.render()` 在非多地形模型下**丢弃 overlay**→ 建筑地图预览全透明
  （严重 bug，已修）；`center=None` 时也可渲染（仅 overlay）；
- overlay 未序列化 → 重开「地图预览」拼件全部丢失；现按名称序列化 +
  `from_dict(pieces=...)` 恢复，建筑导出补写 `map_demo.json`；
- 地图预览对话框在建筑类别下 `session.processed` 为 None 导致崩溃/空图（已修）。

新增测试：`test_canonical_mask_rule`、`test_nearest_mask_fallback_and_full_mapping`、
`test_compose_art_blend_is_symmetric`、`test_overlay_serialization_and_overlay_only_render`、
建筑预览非空回归；全量测试通过。

## 9. 第五轮：2×2×3 地形生成链路严格修正

审查发现三处**致命错误**（已复现证据），是「生成效果非常不好」的直接原因：

1. **裁切窗口 bug（最严重）**：`crop_blocks(img, tile_size=32)` 用
   `cell = min(tile_size, w//6, h//6)` 把「目标瓦片尺寸」当成了裁切窗口，
   对 768×768 的 6×6 生态图**只取了中心 192×192 的一小块**，AI 画的网格被
   整体切错位（复现：右下角格标记完全取不到）。
   修正：`crop_blocks` / `crop_base_3x3` **始终按整图比例裁切**
   （cell = min(w//cols, h//rows)），目标尺寸只由 `normalize_tileset` 归一。
2. **提示词与请求尺寸矛盾**：提示词写「每格 32×32 像素」，而实际请求
   768×768（每格本应 128px）→ 模型按文字画出小网格并在四周留白，进一步
   加剧错位。修正：新增 `grid_cell_px()` 统一计算
   「请求边长 = 格数 × 单格像素（32/64 的倍数，≤2048）」，并把同一数值写进
   提示词（生态/建筑 6 格、经典 3 格），工作流日志同步打印。
3. **几何契约缺失**：原提示词只说「smooth transitions」，AI 可能把边界画在
   1/3 处或让特征填满整格，而我们的四分之一块拼接**要求边格严格沿中线对半、
   角格外侧 1/4 为基础**。修正：提示词改为逐格几何契约（top/bottom/left/right
   边格的哪一半是基础地形、角格 1/4 + 圆角弧、基础块 9 格同一无缝纹理且
   跨块像素级一致），并显式禁止透明度/空区/装饰物。

附带质量改进：
- `normalize_tileset` 缩小改用**块众数降采样**（全向量化、确定性），
  4 倍放大的像素画可被精确还原，不再点采样丢格色；
- 建筑提示词同步改为同一几何口径（6×6 格、边长=$cell×6、墙体中心格必须
  填满整格、其余格纯白待抠除）。

新增测试：`test_crop_uses_whole_sheet_not_center_window`（整图裁切回归）、
`test_grid_cell_px_is_multiple_and_within_limit`、`test_mode_downscale_recovers_pixel_art`、
`test_ground_request_size_matches_prompt`、`test_classic_request_size_matches_cells`、
`test_building_request_size_matches_cells`、提示词几何契约断言；全量测试通过。

## 10. 第六轮：按「示意图.png」参考修正拼装映射与风格

用户提供参考图（`示意图.png`，526×528）作为期望效果。对其做定量分析

1. **拼装取块：从「下半/右半四分之一」改为「同侧四分之一」**（`_ART_SRC`）。
   旧实现假设 AI 把边界画在**中线**（取源瓦片下半/右半），而参考图画在**外侧 1/4**，
   于是条带被挪到目标瓦片中线甚至整条丢失 → 相邻瓦片交界纹理/描边错位
   （用户反馈「拼接很烂」的核心原因之一）。

   对 AI 画在 1/4 或 1/2 处**都能正确对位**（1/2 时两种取法等价）。
2. **内角改用对角瓦片旋转 180° 的负形**。旧实现外角/内角不分，内角也用本角凸角
   艺术 → 内角处出现错误圆角/缺口；现在内角（对角为另一种地形、两侧同类）取
   `rot180(对角瓦片)` 的同侧四分之一，得到正确凹角。

提示词同步改为参考图口径：特征块 = 「一整块圆角团块 + 外侧约 1/4 条带

## 11. 第七轮：基础地形块位置自动识别（防「整张图角色错位」）

### 问题
裁切后的角色分配原来是**纯位置约定**：`blocks[0][0]` 恒为基础地形，其余三块按
右上/左下/右下对应特征。但生图模型经常不守位置要求——真实例子是用户的
`示意图.png`：纯基础地形块在**右上**，冰水塘在左上。此时按位置约定会把「水塘团块」
当成地面纹理、把纯地面当成一个「特征地形」，整张瓦片集彻底不可用（且因为裁剪
无误、流程不报错，属于最难排查的一类失效）。

### 判据（几何契约的逆命题）
特征块的结构是「中心格=纯特征，外侧约 1/4 条带=基础地形」，因此**外侧带颜色与
中心格颜色必然不同**；基础地形块则处处同一纹理。`block_base_score()` 打分：

1. `ring_gap`（主项）：外侧带像素到**中心格中位色**距离的**中位数**——中位数对邻块
   溢出的碎石/装饰点稳健（参考图右上块的外侧带就混入了水塘的岩边碎点）；
2. `centre_spread`：中心格自身的杂色度（特征纹理比纯地面花）；
3. `block_std`：整块亮度标准差——防止「团块画得太小、中心格仍以基础色为主」时被
   误判成地面（此时唯一暴露它的是整块的强对比）。

`detect_base_block()` 取得分最低者并给出可信位：
- 四块得分都高（AI 压根没画纯基础块）→ 回退左上并标不可信；
- 最优与次优几乎同分（例如两块都是同一地面）→ 仍取最低分，但标不可信。

## 12. 第八轮：格线框清理 / 彻底禁文字 / 47 拼接算法重写（对齐式构图）

用户反馈（真实生图底图）：① 底图每格有明显**深色线框**；② 底图上偶尔出现
「草地」这类**文字**；③ 由底图推导的 47 瓦片**衔接明显有问题**。

### 12.1 根因诊断（先复现，再改）
用「参考图口径 + 每格 2px 深色线框」合成底图跑一遍旧管线，成品地图上出现**规律性
深色网格**——线框被四分之一块抠图当成艺术内容拼进了每一张瓦片。此外旧实现还有
两个结构性缺陷：
- 条带/描边等「另一方地形」的像素来自 **AI 的边格**，与基础地形瓦片的纹理**相位不同**
  → 交界处颜色/图案跳变；
- 逐块抠图依赖 AI 把边界画在格内哪个位置、九格是否连续，AI 一换画法就错位。

### 12.2 清理流程（新增 `core/tilemap/cleanup.py`）
- `strip_grid_frames()`：在候选格线位置比较「线带 vs 两侧参考带」亮度中位数，
  显著更暗才判定为线框（参考亮度取**较暗一侧**，避免深色地形贴着线时判成更宽的线）；
  用带外最近两像素的**下中位数**填回（取真实像素、不做平均，不会在「地形色边界正好
  落在格线上」时留下中间色涂抹带）。图像外缘的线框也一并处理。
  清理后的底图另存 `artifacts/tileset_sheet_clean.png`，界面上确认底图时预览的就是它。
- 文字：`detect_text_marks()` 用**等宽细笔画签名**（笔画宽度众数占比 ≥0.35 且细笔画
  ≥6 条）+「多段细笔画/多个等高小块」判据；实测「草地/雪原/GRASS/water/12」全部命中，
  而岩石、草丛、菱形贴花、碎石、纹理噪点**零误报**。命中后 `patch_marks()` 用「自身纹理
  平移半格」的副本覆盖，并把修补写回清理后的底图（预览、产物与成品一致）。
  检测在**源分辨率**的原始格上做（归一化后笔画会被压碎），四块中心格都查。
- 纹理兜底：基础地形的纹理由**九格逐像素中位数**（`median_tile_texture`）得到——
  只画在个别格里的文字/签名/贴花会被「投票」掉。

### 12.3 47 拼接重写：对齐式构图（AI 纹理 + 程序化几何）
`compose_art_tile()` 不再逐块抠 AI 九宫格，而是只用 AI 的**纹理与实测参数**：

| 元素 | 来源 |
|---|---|
| 特征纹理 | 该地形中心格 → 去外框 → 偏移缝合 → 缩放到瓦片尺寸 → **再缝合一 次**（缩放会破坏边缘相等性） |
| 另一方地形纹理 | 基础地形块的九格中位数纹理（所有地形共用同一份） |
| 条带厚度 band / 描边宽度 rim / 描边色 | `measure_terrain_art()` 从 AI 边格实测：从外向内第一个「像特征色」的像素深度（四侧三格取中位数）、条带内明显暗于地面的像素宽度与颜色 |
| 几何 | 暴露侧画 band 宽的地面条带；转角处内边界为半径 band 的圆弧（外角：把地形的角切掉、地面沿弧补齐，弧与两侧直边**相切**；内角：角上半径 band-1 的地面凹口，保证沿边长度正好 band）；描边 = 地面内侧的等宽带（**圆盘**膨胀，方形膨胀在对角方向会多出 √2 倍宽） |

**无缝由构造保证**：所有瓦片取同一份「网格对齐、左右/上下边缘逐像素相等」的纹理，
几何只依赖位掩码 → 相邻瓦片共享边像素相等（仅在转角 ±(band+2) 像素内，两条描边线
交汇处允许 1-2 像素差异）。这同时消除了「AI 画在 1/4 还是 1/2、格子是否连续、有没有
线框」的全部影响。基础地形块 `plain=True` 不实测（它本来没有边界），避免底图脏像素
污染地图外缘的边框线。

### 12.4 提示词
新增 `NO_TEXT_RULE`（三个类别的提示词全部追加）：显式禁止任何文字/字母/汉字/数字/
标题/标签/签名/logo/水印/箭头/UI，并要求**不得写材质名**；同时禁止格线/边框/表格线/
分隔框，强调「格子之间只能由画面本身区分，画面要连续跨过格线」；负向词表同步补齐
（frames、table lines、letters、font、caption、logo、signature、stamp…）。

### 12.5 验证
- 单元：`tests/test_tilemap_cleanup.py`（14 项）——线框抹除只改线框像素且平坦区与
  「本来无线框」的底图一致；文字 4 组正例全中、5 组自然物零误报；修补后文字色不再
  出现；九格中位数能抹掉单格文字；对齐式纹理边缘相等；随机多地形地图共享边在非转角带
  逐像素相等；条带/描边实测结果（1/4 + 1/16 → 32px 瓦片 band=10、rim=2）；
  工作流级（清理日志 + 清理后底图落盘 + 成品瓦片不再含线框颜色；文字告警 + 修补）。
- 端到端目视：合成「参考图口径 + 2px 格线框 + 基础块写字」的底图 → 真实工作流 →
  地图呈现圆角团块 + 连续描边 + 无网格、无文字（清理后的底图也已落盘核对）。
- `tests/test_tilemap_eco.py` 中原「按四分之一块抠图」的断言改写为对齐式构图的

## 14. 第十轮：建筑类链路重写为「墙体 16-tile 族 + 透明外部」

### 旧实现的问题
`process_building_sheet()` 只产出 4 个拼件：整格实心「直墙」、圆盘切两角的「端头」、
圆盘切一角的「转角」、以及 AI 立柱。于是：没有墙体厚度、没有 T 形/十字/内角/外角/
门/顶面，铺出来只能是方块堆叠；而且**没有接缝保证**（相连侧也会被当作暴露面画出
描边，长墙每格出现一道竖线）。

### 新设计（`core/tilemap/walls.py`）
1. **16-tile 族**：墙体是一维路径，一格只需要四个方向是否相连（`n|e|s|w` 四位），
   16 种组合正好覆盖 墙内部 / 墙边 / 墙角（内角与外角同时存在于一块里）/
   T 形（4 向）/ 十字 / 端头（4 向）/ 孤立块；对角位对墙体没有意义。
   槽位 = `n | e*2 | s*4 | w*8`，与地块类的 16 图块族约定一致。
2. **固定截面几何**（关键）：横带的行范围、竖带的列范围只由 `margin` 决定，
   相连只是把带子**伸到那条边**并在中心汇合 —— 因此 A 的 E 位与 B 的 W 位同时
   为满时，两块在共享边上的墙/透明分界完全一致；直墙、T 形、转角之间也不会错位
   （先前「让位深度随另一条轴的连通情况变化」的写法会导致 1 像素错位，已废弃）。
3. **透明外部**：让位区 alpha=0、无半透明、无白边（白底先经白键抠除，轮廓是程序化
   1px 描边，且只在**暴露**边界上画 —— 相连侧不画，长墙因此不会每格一道竖线）。
4. **层次**：朝上/朝左的边界是墙顶（AI 顶面组纹理优先，否则提亮），朝下/朝右的
   边界是立面（压暗），边界朝向由足迹几何算出，因此任何形状的外观规则都一致。
5. **转角**：弯折外角用「角部方形 − 切圆」倒圆（与两条墙面相切）、内角补小圆角；
   倒角可能切出的 1px 孤岛由「只保留最大连通块」清掉。
6. **门与立柱**：门件取自 AI 开口组中心格（贴在直墙上，另有竖直版），
   立柱件取自 AI 立柱组中心格，取不到就程序化生成柱体。
7. **实心件**：额外导出 `solid`（整格不透明）供整片实心区域使用；默认**不**自动
   替换 16 族槽位 —— 实心块与带子家族形状不同，混用会在共享边留下透明/不透明错位。

### 导出与接入
- `build_wall_atlas()`：4×5 = 20 槽图集（0..15 = 16 族，16 = solid，17/18 = 门横/竖，
  19 = 立柱），元数据含 `bits / slots / slot_of_piece / extra_slots /
  mask16_to_slot / mask8_to_slot（256 项）/ transparent_outside`；
- 工作流：`_do_seamless`（建筑）改为 `wall_art_from_sheet` + `build_piece_set` 并
  生成图集；`_do_atlas` 幂等补齐；`_export_building` 导出 `pieces/*.png`（20 张）、
  `walls_16.png/json`，并把演示地图改成「地块铺底 + 墙体透明叠加」的一间屋子
  （外墙 + 上下门洞 + 内部十字墙），直观展示 16 族全部连接件；
- 参数：`TilemapParams.wall_thickness`（墙体厚度占比，默认 0.56）与既有 `edge_noise`
  （墙体带子外侧的起伏，共享边仍逐像素一致）。

### 验证
`tests/test_tilemap_walls.py`（13 项）：16 族完整性与命名、非内部件透明（无半透明、
无近白像素）、实心/十字件的透明比例、带子恰好居中 `[margin, s-margin)`、转角无孤立
像素且为 L 形、**整张墙体地图（外墙 + 内十字）0 处共享边不一致**、长墙相连侧中段
无描边、AI 建筑图推导（纹理网格对齐 + 图集槽位/元数据）、旋转保持透明度。
同时更新了建筑端到端与 GUI 拼件下拉的断言；全量测试通过。

## 16. 第十二轮：类别精简、基础地形无边、素材（道具）链路、墙体实时自动拼接

   代码路径保留以兼容旧项目与测试（默认 category 仍为 classic，仅供 API 调用）。

## 17. 第十三轮：素材抠底加固、素材可叠加与缩放放置、拼件画笔随时可用

针对反馈的三点：

1. **素材背景没抠净 → 抠底加固**（`core/tilemap/props.py`）
   - 背景色改为取**四角小块**的中位色（整条边容易被压边的物件带偏）；
   - 容差**自动升级重试**（38 → 58 → 84 → 120）：AI 的「纯色底」常带轻微渐变/噪点，
     原来固定 38 会留下整块底色；每轮都从四边**洪泛**，只删与边缘连通的同色像素，
     因此物件内部的同色区域依旧不会被挖空；
   - 仍然不透明（物件与背景几乎同色）时做一次**全局同色删除兜底**，宁可输出干净剪影；
   - 抠底后仍占 >85% 格面积会写 warning 日志，便于定位是哪张底图有问题；
   - 页面在素材生成后会显示「已抠背景」的横排预览（棋盘格衬托透明区），一眼可确认。
2. **素材可叠加在地块上**：素材包（`.tilepack`，category=prop）加载进预览后即进入
   拼件画笔，左键铺在地块/建筑之上（overlay 层），与建筑拼件同一机制。
   顺带修掉一个真 bug：拼件下拉原先只在「构造时已有拼件」才创建，
   预览里**后加**的包用不了画笔 —— 现在画笔控件始终存在，按可用性启用/禁用。
3. **素材大小可调**：`TileMapModel.set_overlay(..., scale=…)` 支持放置缩放，
   渲染时以**格子底部中心**为锚点缩放（放大的树仍「站」在同一格地面上），
   并且 `scale` 会写进地图 JSON、恢复后渲染逐像素一致；预览工具栏新增「缩放 %」
   （25%–400%），与旋转、自动墙开关并列。

测试：新增 4 组抠底场景（纯白/洋红/噪点底/物件压边，断言不透明占比 < 0.6）、
背景与物件同色时的兜底、overlay 缩放跨格与序列化一致、后加瓦片包立即可用且缩放在放置时生效；
全量测试通过。
